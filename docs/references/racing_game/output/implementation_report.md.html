Solstice Circuit — implementation and verification

Solstice Circuit is a playable desktop-browser arcade racer: choose one of three cars and race five opponents around a closed desert circuit for three laps. The delivered production build is game/dist/index.html; index.html forwards to it. Use an HTTP server rather than opening module scripts through file://.

Run locally

From output/game, with Node.js and npm installed:

npm install
npm run dev -- --host 127.0.0.1 --port 5187

Open the printed local URL. To test and build:

npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 5188

The saved build requires no network assets. Dependencies are pinned in package.json (Three.js 0.184.0 and Vite 7.3.7); a fresh install requires registry access. No package lock was supplied. In the provided evaluation environment, the installed sandbox Vite CLI and Three.js fallback were used with Node.js 24.21.0. The executed build command from output/game was node ../../../../../../sandbox/node_modules/vite/bin/vite.js build --configLoader native; development used that CLI with --host 127.0.0.1 --port 5187 --strictPort. Both completed successfully. node tests/simulation.test.js ran the simulation suite.

Controls and flow

Input Action
W / Up Accelerate
S / Down Brake, then reverse
A / Left Steer left
D / Right Steer right
C Cycle chase, hood and overhead cameras
P / Escape Pause or resume
R Restart race with selected car
Space Recover heading/position on track without awarding checkpoints

Select a car, choose Take the grid, and wait for the countdown. The HUD shows speed, lap, rank, race time, current/best lap, live classification, camera and minimap. Pause provides restart and garage buttons. After finishing, the race waits for the field and presents final standings; race-again and change-car buttons are available. Keyboard input is cleared and the race pauses on lost window focus.

Architecture and implemented features

src/simulation.js implements rendering-independent vehicle dynamics, exact track projection, AI, collision response, race progression and immutable diagnostic snapshots. src/main.js builds the Three.js scene, cameras, DOM interface, input handlers and animation loop. src/style.css defines the visual presentation; tests/simulation.test.js exercises the model directly.

The approximately 671 m circuit has four straights and four rounded corners. Asphalt, centre markings, edge lines, alternating kerbs, barriers, checkpoint beacons and a chequered start/finish gantry make its boundaries clear. Original procedural geometry supplies desert mountains, rocks, palms, an oasis, paddock, grandstand and signs. Directional shadows, hemisphere light, warm fog, material roughness and a sunset palette give the scene a consistent appearance. Static scenery is batched by material to reduce draw calls. There are no externally downloaded proprietary assets; public/ is intentionally empty because geometry and sign textures are generated in code.

The three vehicles differ in colour, dimensions, trim and spoilers as well as all four driving parameters:

Vehicle Maximum m/s (km/h) Acceleration Braking Handling coefficient
Comet GT 38 (137) 13 25 1.70
Spectre R 44 (158) 10 21 1.38
Swift RS 34 (122) 16 30 2.05

Driving uses a fixed 120 Hz simulation step, throttle and braking acceleration, rolling/speed-related drag, smoothed steering and reduced yaw response at higher speed. This is an arcade planar physics model rendered in 3D. Chase view follows behind with speed-dependent field of view; hood view places the camera near the front of the selected vehicle; overhead follows from above.

Five opponents steer and accelerate using the same dynamics and collision system as the player. Look-ahead steering follows the track, anticipated bends reduce target speed, nearby traffic triggers lane changes and braking, and tyre obstacles trigger avoidance. A blocked NPC realigns at its current track progress after approximately 2.5 seconds. NPCs are not moved along a prerecorded animation path. Their decisions are deterministic heuristics, not optimal racing tactics.

Track-side confinement, circular car contacts with momentum transfer, and circular tyre-stack contacts provide collision response. Two position-resolution passes reduce overlapping contacts; impacts reduce or reverse speed and visibly flash the affected car and player vignette. Major reachable obstacles are tyre stacks. Decorative scenery lies outside the enclosing barriers and has no separate vehicle collider.

Sixteen ordered checkpoints validate each lap. Forward crossing, a bounded local progress increment and the expected checkpoint sequence prevent a finish-line shortcut, reversing over a gate or a large position jump from awarding a valid lap. Three laps require 48 checkpoint crossings. Position uses validated progress and finish times; lap times and final standings are retained. Recovery changes heading and lateral position at current longitudinal progress without skipping checkpoints.

Known limitations and interpretation

The collision bodies are circular approximations rather than oriented chassis hulls; tight contacts can look coarse or temporarily trap a player. Space provides explicit recovery. AI can collide and lose time and does not guarantee optimal overtakes. Vehicles are constrained to a flat track; there is no suspension or off-road exploration. The hood camera is a simple hood view, with no full cockpit interior. Camera switching and the tested views were usable, but camera obstruction avoidance is not a general raycast collision system. Finishing cars continue circulating until the complete field has finished.

This is a keyboard-focused desktop game, with no touch controls, audio, multiplayer or saved progression. Low frame rates clamp accumulated simulation time, so simulated race seconds need not equal elapsed wall time. Testing used Chromium on this Windows host; it does not establish exhaustive browser, GPU, accessibility or long-duration coverage. A fresh network-based dependency installation was not performed during this completion pass.
